One dropped internet connection showed me a bug that had been there all along.

A test run failed with a normal network error, the kind that fixes itself if you try again a few seconds later. But my system had labelled it "permanent". Permanent errors aren't retried.

The cause was small. The error library wraps the real network error inside another one, and my code only read the outer layer. So every dropped connection, on every platform, looked permanent.

That meant scheduled posts that hit a blip would never be retried. They'd just quietly fail.

Fixed now, with tests that reproduce exactly what the library throws.

If you're automating marketing (scheduled posts, ad changes, reports), here's what I'd check in your own setup:

1. Can it tell a temporary failure from a permanent one? "Try again later" and "this will never work" need different handling.
2. Does it retry the temporary ones, with a limit?
3. Does anyone find out when something fails? A scheduler that has stopped looks exactly like one with nothing to do. I added an alert for exactly that.

Most automation doesn't break loudly. It stops doing things, and nobody notices for a week.
